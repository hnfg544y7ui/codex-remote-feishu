# 飞书群话题多会话

> Type: `implemented`
> Updated: `2026-10-13`
> Summary: 记录同一机器人在群内通过固定话题分别控制 Codex 会话的操作、路由和恢复边界。

## 使用步骤

把已配置的机器人加入飞书群。首次操作显式 `@机器人`，避免群普通消息权限或主机器人设置使消息未被接收。

1. 在群主聊天发送 `@机器人 /topic new 开发任务`，机器人会在这条消息下回复话题欢迎卡。
2. 打开该话题，在话题内发送 `@机器人 /use`，选择项目以及已有会话，或从选择器新建会话。
3. 在这个话题内发送任务。首次选定会话后，该话题固定绑定此会话。
4. 回到群主聊天，再发送 `@机器人 /topic new 另一任务`，在第二个话题选择另一个会话。分别进入两个话题对话，无须切换同一个群会话的目标。

命令说明：

| 命令 | 发送位置 | 功能 |
| --- | --- | --- |
| `/topic` 或 `/topic list` | 群主聊天或话题 | 查看本群话题入口和绑定状态；已有飞书消息链接时展示链接。 |
| `/topic new 名称` | 群主聊天的一条新文本消息 | 创建独立话题入口；名称省略时使用“新会话”。 |
| `/use` | 尚未绑定的话题 | 选择项目及会话，完成第一次绑定。 |
| `/topic close` | 要关闭的话题 | 关闭空闲话题，保留绑定记录；运行、排队或待确认期间拒绝关闭。 |

菜单“话题会话”提供查询入口。创建必须发送新文本，不能从旧卡片回调创建，也不能在已有话题中再创建嵌套话题。

## 群消息与并发

需要机器人承接未 `@` 普通群消息时，可在群主聊天执行 `/primary on`，并确认机器人具有相应群消息权限。权限未开放时继续显式 `@机器人`；设置主机器人不会自行授予飞书权限。如果网关配置为 `group_at`，仍需在每条话题消息中显式 `@机器人`；`/primary on` 不改变网关的消息接收模式。

要同时执行两个话题，可在群主聊天执行 `/coworkers 2`。该值沿用本群已有的共享运行上限；`0` 表示不限制。创建话题不修改现有并发设置。

不同话题具有独立的会话选择、队列、附件、审批和历史入口。相同话题中的任务仍按原有队列串行；等待群并发名额的任务保留在该话题队列。运行名额按照群统一计数，不能通过多建话题绕过上限。

首版只允许话题创建者向该话题发送任务、操作会话和回答审批。同群其他成员可以看到群内话题与列表，但不能接管别人的话题。同一 Codex 会话也不能绑定到多个话题并行执行；请选择不同会话。

## 固定绑定与关闭

话题名称是显示信息，话题身份由机器人、群和创建命令的飞书根消息共同确定，不随会话名称改变。

第一次会话绑定后，不能用 `/use` 切换到其他会话，也不能用 `/new`、`/follow` 或后端切换绕过绑定。需要另一个会话时，在群主聊天创建新话题。绑定后也拒绝用 `/detach` 或 `/workspace detach` 解除绑定。网络中断不解除话题绑定，恢复时只能接回原会话。

`/topic close` 不终止正在执行的任务。空闲关闭后保留话题及原会话绑定的关闭记录，后续输入不能自动重新打开；需要继续使用时创建新话题并选择原会话。重复投递同一条创建命令不会重建或清空已存在话题。

## 路由与卡片安全

所有话题输出都回复到固定根消息并使用飞书线程回复，包括欢迎、选择器、确认、进度、答案及文件。线程回复失败时报告失败，不降级发送到群主聊天，避免把一个话题的结果发送到另一个入口。

回调同时校验真实群、根消息、原生飞书话题以及已知消息归属。转发卡片携带的目标字段不能单独建立路由。仍保留 daemon lifecycle 与旧卡片检查；重启前的卡片不能继续执行操作，应发送新命令获取新卡片。

## 重启与当前边界

话题根消息、原生话题标识、创建者、名称、固定会话绑定和关闭状态持久化，重启后按原话题恢复，不继承群主聊天的项目或会话。话题回调关联所需的已知输出消息标识也保存，保留有限的近期集合。

首版拒绝需要独立辅助会话的审阅、临时分叉，以及在已绑定话题中执行定时任务的“每轮新建会话”计划；这些操作请通过机器人私聊使用，不能静默改为本话题会话。

当前队列仍沿用既有内存执行模型：绑定恢复不代表运行中的任务或全部排队输入具有可靠持久化，进程崩溃不能承诺自动重放已接收任务。对执行结果未知的任务应查看原会话历史后决定是否重新发送，避免重复操作。

本功能按单个 Remote daemon 管理群话题，不提供多主机统一会话目录或跨主机调度。现有私聊及普通群模式保持原有入口。是否收到群消息、是否支持线程回复及模型网络是否可用，需分别验证；本地单元测试不能替代飞书群内的实际验收。
